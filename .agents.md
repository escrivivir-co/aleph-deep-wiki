## 📝 **Historial de Problemas ANTIGUOS (Ya resueltos)**
Se modificó `deepwiki.bat` para pasar solo el nombre del repositorio (`as-core`) en lugar del path completo (`/app/repos/as-core`), dejando que el script ETL construya el path internamente.

### **Problema 4: Docker ENTRYPOINT duplicaba comandos**

**Descripción:**
El Dockerfile ETL tiene `ENTRYPOINT ["python", "etl.py"]` pero el script `deepwiki.bat` llamaba `python etl.py as-core`, causando ejecución duplicada: `python etl.py python etl.py as-core`.

**Síntomas:**
- El script ETL recibía `'python'` como primer argumento en lugar del nombre del repositorio
- `sys.argv[1]` era `'python'` en lugar de `'as-core'`

**Solución Aplicada:**
Se corrigió `deepwiki.bat` para pasar solo el argumento (`as-core`) sin `python etl.py`, ya que el ENTRYPOINT del contenedor ya maneja esto.

### **Problema 5: Repositorios locales sin configuración git**

**Descripción:**
El script ETL asumía que todos los repositorios locales tenían configuración git válida con remote origin. Los repositorios copiados con `copy-repo` no tienen `.git` o no tienen remotes configurados.

**Síntomas:**
- "Error actualizando repo: /app/repos/as-core" durante la indexación
- El proceso se detenía sin procesar archivos
- `git.InvalidGitRepositoryError` o fallos en `git pull`

**Solución Aplicada:**
Se mejoró `etl/etl.py` para manejar repositorios locales sin git:
```python
try:
    repo = git.Repo(repo_path)
    if repo.remotes:  # Solo hacer pull si hay remotes configurados
        repo.remotes.origin.pull()
        print(f"✓ Repositorio {repo_name} actualizado desde remote")
    else:
        print(f"✓ Repositorio local {repo_name} sin remote - usando archivos existentes")
except git.InvalidGitRepositoryError:
    # No es un repositorio git válido, probablemente copiado con copy-repo
    print(f"✓ Repositorio local {repo_name} (copia de archivos) - procesando directamente")
```

### **Problema 6: Configuración de networking Docker en Windows**

**Descripción:**
Los contenedores no podían conectarse a Ollama externo usando `host.docker.internal` en Docker Desktop para Windows.

**Síntomas:**
- `404 Client Error: Not Found for url: http://host.docker.internal:11434/api/generate`
- API Q&A funcionaba para conectar a ChromaDB pero no a Ollama
- OpenWebUI no podía conectarse a Ollama externo

**Solución Aplicada:**
Se agregó `extra_hosts` a todos los servicios en `docker-compose.external-ollama.yml`:
```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```
